# Dragon Survivor — Plan 2: Ataques y evoluciones doradas

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** Sustituir el sistema de mejoras por 4 huecos de ataque con 5 niveles, 7 estadísticas y evoluciones doradas (spec 6.4).

**Arquitectura:** Las reglas (qué cartas se ofrecen, cuándo sale la dorada, qué números tiene cada ataque en cada nivel) viven en `src/logic/attacks.ts`, puro y con tests. Cada ataque es una clase `Weapon` en `src/game/weapons/` que lee su nivel y si es dorado de `RunState` en cada disparo, así que subir de nivel no recrea nada. `GameScene` guarda un `Map<AttackId, Weapon>`.

**Tecnologías:** las del Plan 1 (Phaser 4.2.1, TypeScript, Vitest, Playwright).

**Spec:** `docs/superpowers/specs/2026-11-12-dragones-survivors-design.md`, sección 6.4.

## Restricciones globales

- Máximo **4** ataques. Máximo nivel **5** en ataques y estadísticas.
- Estadísticas: fury +10 % daño, thick_scales +20 vida, quick_breath −8 % recarga, swift_wings +8 % velocidad, regen +0,5 vida/s, armor −1 daño, magnet +20 % radio.
- Afinidad: ×1,25 de daño si el ataque es del elemento del dragón.
- La carta dorada sale **seguro** cuando hay un ataque a nivel 5 con su estadística clave (≥1) y aún no es dorado.
- Todo texto visible pasa por `t()` en es/en. Sin objetos nuevos por frame fuera de pools.
- Las reglas del Plan 1 siguen en pie (pools, delta acotado, botones con `onTap`).

## Riesgos a revisar

1. **4 huecos llenos y elemento fijado:** nunca debe ofrecerse un ataque nuevo; los que llevas de otro elemento sí se pueden subir (test en Task 1).
2. **Escupitajo a nivel alto al evolucionar:** el aliento hereda el nivel y ocupa el mismo hueco, sin duplicar armas (test en Task 2).
3. **Dos ataques listos para dorado a la vez:** sale una dorada por subida de nivel, en orden estable, y la otra en la siguiente (test en Task 1).
4. **Dorada cogida con la pantalla girada o con el joystick pulsado:** mismas protecciones que las cartas normales (ya cubierto por `onTap` y `relayoutOnResize`; test en Task 4).
5. **Muchos enemigos y los 4 ataques dorados:** 30 fps mínimo y pools estables (test en Task 5).

```ts
export const MAX_SLOTS = 4; export const MAX_LEVEL = 5; export const AFFINITY = 1.25;
export interface AttackDef { id: AttackId; tag: Tag; key: StatId | null; offered: boolean }
export const ATTACKS: Record<AttackId, AttackDef>; export const ATTACK_IDS: AttackId[]; export const STAT_IDS: StatId[];
export type Owned = Partial<Record<UpgradeId, number>>;
export interface Loadout { owned: Owned; element: Element | null; gold: AttackId[] }
export type Choice = { type: 'upgrade'; id: UpgradeId } | { type: 'gold'; id: AttackId } | { type: 'fallback' };
export function isAttack(id: UpgradeId): id is AttackId;
export function tagOf(id: UpgradeId): Tag;                         // estadísticas → 'neutral'
export function heldAttacks(owned: Owned): AttackId[];             // en el orden de ATTACK_IDS
export function availableUpgrades(l: Loadout): UpgradeId[];
export function eligibleGold(l: Loadout): AttackId[];
export function rollChoices(l: Loadout, rng: () => number, count?: number): Choice[];
export function breathFor(e: Element): AttackId;
export function spitToBreath(owned: Owned, e: Element): Owned;      // copia: mueve el nivel de spit al aliento
export interface AttackParams { damage: number; cooldown: number; count: number; radius: number; extra: number }
export function attackParams(id: AttackId, level: number, gold: boolean): AttackParams;
export function computeStats(stage: Stage, owned: Owned): PlayerStats;   // sustituye a la de stats.ts
```
`extra` guarda el dato propio de cada ataque: saltos (lightning_breath), empuje (roar), ralentización (frost_aura), objetivos (static_field), radio de zona (fire_breath).
